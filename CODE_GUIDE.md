# Code Guide - read this before the demo

Goal: be able to explain every file in your own words and make a small change live.

## 1. How one request flows
1. Every page starts with `define('APP_RUNNING', true);` then `require php/bootstrap.php`.
2. `bootstrap.php` loads the config + database (`php/db.php`), sends the security headers, starts the session, and defines helpers: `e()`, `csrf_*`, `log_event()`, lockout and IP-block functions.
3. The page checks its own rules (logged in? admin? CSRF token? CAPTCHA?), does the work with prepared statements, then shows HTML using `page_header()` / `page_footer()` from `php/layout.php`.

## 2. File by file
| File | What it does |
|---|---|
| `php/db.php` | Reads config (outside web root), connects with PDO, holds the fixed class settings (`$SEED`), has `encrypt_data()` / `decrypt_data()`. |
| `php/bootstrap.php` | Headers, session settings, CSRF, CAPTCHA check, activity log, lockout, IP block, idle timeout. |
| `php/validation.php` | One function per rule (`v_name`, `v_email`, `v_password`...). Each returns an error message or `null`. |
| `php/mailer.php` | Sends email with PHPMailer. Holds the OTP email, lockout alert and password-changed alert. |
| `php/otp.php` | Makes, sends and checks the 6-digit code. |
| `php/layout.php` | Header, footer and form-field helpers (`field()`, `select_field()`, `password_field()`). |
| `php/dashboard_data.php` | The read-only SELECT queries for the dashboard. |
| `register.php` | Registration as a 6-step form (the steps are shown/hidden by `js/script.js`; without JavaScript all steps show). Validation + saving the user. ID Number is generated by `next_id_number()`. |
| `login.php` | Username + password + CAPTCHA, lockout, then sends the login OTP. |
| `otp.php` | One page for the register / login / reset codes. |
| `forgot.php` | Username + CAPTCHA, then a security question, then the reset OTP. |
| `change_password.php` | Only opens if `$_SESSION['reset_ok']` exists. Checks strength + last 3 passwords. |
| `home.php`, `book_appointment.php` | Resident pages: profile, booking, cancelling. |
| `admin_appointments.php`, `dashboard.php`, `api.php` | Admin-only pages and the JSON endpoint. |
| `scripts/monitor.php` | Command-line scan of the log that writes `security_flags`. |
| `js/script.js` | Browser validation, strength meter, username check, countdowns, idle warning. |
| `js/dashboard.js` | Draws the dashboard. Uses `textContent` so attacker text cannot run. |

## 3. Questions you may get (short answers)
- **Why prepared statements?** The SQL and the user's data travel separately, so `' OR '1'='1` is just text.
- **Hash vs encrypt?** A hash cannot be reversed - for passwords, answers, OTPs. Encryption can be reversed with the key - for blood type, which we must show to its owner again.
- **How does lockout work?** `record_failure()` adds 1 to `lockouts.failures`. At 3, 6, 9 it sets `locked_until` (seeded seconds). The server checks `locked_until` before it checks the password, so reloading or clearing cookies does nothing.
- **Why the same message for a wrong username?** So an attacker cannot learn which usernames exist. We even run `password_verify` against a dummy hash so the timing matches.
- **How does Forgot Password stay safe?** `otp.php` sets `$_SESSION['reset_ok']` only after the correct reset code. `change_password.php` refuses to open without it and deletes it after use.
- **Why regenerate the session ID?** So a stolen pre-login session ID is useless after login (session fixation).
- **Why is the log insert-only?** If an attacker gets in, they cannot erase their tracks. No file runs UPDATE or DELETE on `activity_log`.
- **What does the honeypot do?** A hidden field humans never fill. If it has a value, a bot did it, so we quietly refuse.
- **Why can't a JS file really be hidden?** A script tag and a typed address send the same request. Real protection is server-side checks.
- **How does `monitor.php` find OTP guessing?** It lists each user's OTP_FAILED times and slides a 10-minute window over them; 5 or more means a flag.

## 4. Live-change cheat sheet (practice these!)
| New requirement | Where to change |
|---|---|
| Change a lockout time, OTP expiry, idle timeout, password length | The `$SEED` array in `php/db.php`. |
| Change what counts as a strong password | `pw_strength()` in `php/validation.php` AND `strength()` in `js/script.js`. |
| Add a registration field | 1) column in `sql/schema.sql` / ALTER TABLE 2) `v_...` in `php/validation.php` 3) `$keys`, validation and INSERT in `register.php` 4) the form line 5) show it in `home.php`. |
| Lock after 5 failures instead of 3 | `$f >= 3 && $f % 3 === 0` in `record_failure()` (`php/bootstrap.php`). |
| New log event | Call `log_event('NAME', ...)` where it happens, add `'NAME'` to `EVENT_TYPES` in `php/dashboard_data.php`. |
| New monitor pattern | Copy one block in `scripts/monitor.php`, change the query and the `add_flag()` text. |
| Change IP block time | `INTERVAL 10 MINUTE` in `maybe_block_ip()`. |
| Change the footer / header text | `page_header()` / `page_footer()` in `php/layout.php`. |
